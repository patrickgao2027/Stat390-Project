## What did the agent do well?

The agent is very good at improving upon itself through iterations in attempts at reaching the goals set out by program.md. At first, I gave the agent a direction to build the model.py, but eventually the agent was able to make independent decisions and self corrections to achieve better performance. Multiple tasks such as writing code, pushing edits, running code, and appending to results that would have taken humans hours to complete were done within minutes by the agent. After the 14th iteration, the agent was fully able to follow the program.md protocol with proposing only one edit such that results can be interpreted as flowing from the change. Prior iterations did have performance improvements, however there were multiple instances of more than one edit being proposed. This led to results being uninterpretable as to why they occurred. Iteration 26 was a good demonstration of the Auto Research conditions. A single variable was changed, but the results showed regression. The edit was reversed and another direction was explored by the agent. The agent also caught iterations 4, 5, and 7 having multiple edits and listed them as confounded. After the nondeterministic methods were discovered in iterations 20 and 21, the model was still able to show that results were due to actual improvements in model performance and not random chance. In the end, the agent also wrote code to save the model and show that even through accidental random processes in the frozen code blocks, iteration 35 could be reproduced once the model is saved.

---

## What did the agent do poorly?

For iterations 4, 5, and 7 the agent made more than one edit to model.py that led to improvements in model performance. However due to not following the instructions set out by program.md, the results were uninterpretable as to which edit led to better results. This led to subsequent iterations having to retrain to find out which changes led to the improvements. Iteration 13 and 15 both had results that went over the recall goal, however similar training runs had recall metrics below the goal. The agent interpreted this as a reason to stop Auto Research as the recall and ROC-AUC goals were complete. The loop should not have ended because the results over the goal were due to random processes. Lastly, the agent does not update CLAUDE.md unless prompted. This is bothersome because information is not updated for new agent sessions and could lead the agent to make errors due to not having updated information.

## What required human judgment?

The human was required to write the program.md file that led the agent on its goal and pathways to explore after the baseline run through. Human judgement was required to set achievable goals given the hardware limitations, performance of other models trained with the dataset, and knowledge of current image classification models. It was required for the human to have some knowledge of image classification so that the agent could be pointed in the right direction and to evaluate the agent's thinking. The human is also responsible for writing the prepare.py and run.py files which are frozen and cannot be edited by the agent. Those two files must create the correct environment for Auto Research to iterate through as once iterations start, the prepare.py and run.py files must be kept frozen for consistency throughout the experiments. This is likely the most important step for humans. Another important task for human judgement is evaluating the model performance after iterations and potentially prompting the agent to go in a different direction. This task can be delegated to the agent, however if the agent continues down a path that does not show improvement, human intervention is needed via interpretation of the model performance and code.

## How would you redesign the loop?

I would spend more time self coding the prepare.py and run.py files in order to remove all nondeterministic elements that are embedded within them. The prepare.py file had image augmentations that were dependent on random seeding that did not get assigned a random seed. This nondeterminism was discovered in iteration 20 when the EfficientNet-B2 model was assigned a set seed for training runs, but different results were seen in iteration 20 and 21. This means that I failed to check for nondeterminism in my Auto Research set up. I had to keep the prepare.py file frozen in order to keep results consistent across iterations. In the future, I would go through and double check to ensure that no mistakes were made in the initial set up for Auto Research. Another edit I would make is to not give strict guidelines on where the agent should build after the baseline. This would give the agent more freedom to explore different avenues apart from the path I give it. Lastly, I would remove the constraints that the build_model() function must have .fit, .predict, and .predict_proba methods. I added these constraints so that the sklearn metrics could be used, but allowing the agent to find its own way to get results that can be used with sklearn metrics could be a better method.

## What did you learn about doing research with AI agents?

I learned that doing research with AI agents is a powerful tool to quickly build software and machine learning models that work with complex data types. AI agents are able to quickly build the framework of an entire software ecosystem for a machine learning model. Through the first few edits of the model, the model is almost reaching its maximum performance given the hardware constraints. After multiple iterations, the agent will explore pathways to eventually converge to a best performance. This is very advantageous for building machine learning systems quickly and efficiently. However, there are some challenges when doing research with AI agents. One big mistake that I made during my project was not seeding everything that could be random during my initial Auto Research loop set up. This led to issues in further iterations as I could not edit my frozen files to ensure consistency across Auto Research loops. Another issue is the general uninterpretability of the code base. Due to the massive amount of changes that are occurring in each iteration, it is difficult to keep track of what the agent is doing to the code. Although the agent does give an explanation of their reasoning behind the edits in the prompt window, oftentimes it is difficult to understand or too wordy. Lastly as a programmer, I have trouble understanding the code base written by the agent because I did not write it or was not given a manual detailing specific reasoning behind the code written. I would say that research with AI agents is a great tool for exploring directions to build machine learning models without dedicating too much time. In practice this would be useful for experimenting with new ideas, but not for working in actual company codebases or on academic research projects.
